# 部署与运维

本次真正验证的拓扑是 Windows 本地应用 + 既有 VMware Linux Docker 存储服务。没有修改旧 Compose、移除容器/镜像/卷或业务数据。当前源码包不把“写了 Dockerfile”当成已完成容器部署，因此没有未经验证的公网地址。

## 日常流程

1. 保持已有 VM 网络和 Docker 服务正常，先 `doctor.py` 执行真实检查。
2. `start-local.ps1` 启动一个应用进程；`/health/live` 存活后前端再查 readiness。
3. 导入前确认模型缓存与账户余额。数据写入独立 bucket / 集合 / DB。
4. 故障先查看任务节点、错误类型和本机日志。原始 SDK 错误可能含服务端元数据，`data/` 与 baseline 日志均不发布。
5. `stop-local.ps1` 发送项目专用停止文件，给进行中的任务90秒退出期限。不以端口扫描后强杀方式关停其他程序。

## 备份和回退

变更前已保留原源码备份。Git 中的代码回退不等于数据回退；处理配置进入版本哈希，新旧资料版本可同时保留。备份 SQLite 应使用数据库备份方式或停服复制，并单独备份 Mongo manifest 与 MinIO 对象。这里提供策略说明，未执行用户数据库的全量备份或恢复演练。

模型revision变化时拒绝与旧向量混搜，使用新的索引 namespace 或显式新版本导入。不要 drop_collection 后假设数据可以恢复。当前孤立的未提交对象只记录，不自动删除。

## 上公网前的必要工程工作

课程衍生源码公开许可确认；MinerU已安装版本许可审查；正式身份系统与会话过期策略；TLS和反向代理；任务队列与跨进程锁；速率限制、指标与容量测试；可恢复备份；独立密钥管理；最小网络权限。当前localhost演示没有冒充这些能力。

VM诊断脚本要求显式传入 `-VmHost`；SSH密码只能在本机终端输入，不进聊天或日志。修改VM时间脚本只在用户确认时手动运行，本项目不会在启动时自动改系统时钟。
