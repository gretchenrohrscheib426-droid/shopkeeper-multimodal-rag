# 实时演示脚本

## 演示前检查

运行 `start-local.ps1`，前端显示服务就绪；登录使用APP_API_TOKEN。已有原创手册与教育文档已经实际入库。现场只展示有公开权利的原创手册，避免把课程原文展示给未授权观众。先打开本机验证报告，说明真实模型及本次失败数字。截图用于文档佐证，不替代现场运行。

## 3分钟版本

|时间|动作|讲述|
|---|---|---|
|0:00–0:25|打开工作台与文档列表|三种格式统一进入可追溯版本，后端连接真实存储和模型|
|0:25–0:55|上传原创两页PDF，展示各节点事件|MinerU解析、VLM图片摘要、MinIO核验和向量写入；首次通常约一分钟，现场等待真实状态|
|0:55–1:35|选择手册问“单个上传文件大小上限是多少？”|展示实际返回的40 MiB和引用；不预填模型答案|
|1:35–2:05|展开引用，打开原文和图片|片段、processed MD跨度、真实PDF和图片由鉴权接口读回|
|2:05–2:30|问“资料中没有的超级管理员密码是什么？”|观察资料不足；不把模型常识当来源|
|2:30–3:00|展示评测摘要与源码|59/60首轮、冻结20/20；解释一次引用校验失败与工程边界|

若重复上传已处理过的同版本，页面应显示复用；若希望演示首次处理，用新来源名称会创建独立演示资料，事后不会自动删除。不要把去重复用的毫秒级耗时说成首次完整导入速度。

## 8分钟版本

1. **0–1分钟：问题与架构。** 文档中的图、表、流程不能仅靠文件名搜索；展示两图、三存储及任务日志。
2. **1–2分钟：真实导入。** 上传DOCX图文表格或PDF，观察实际节点，解释PDF与Word解析分工。浏览器Markdown单文件不携带邻接图片。
3. **2–3分钟：三类问答。** 问上传限制、PDF/DOCX用途、图中S1/S2/S3顺序，逐一点击真实引用。
4. **3–4分钟：会话。** 追加“那第二步呢？”，展示历史改写；刷新页面看历史恢复。新会话自动范围问“这个怎么用？”观察澄清选项。
5. **4–5分钟：异常。** 发起后取消，观察cancelled；展示已保存的真实断连/401/超时测试报告，不现场关闭用户数据库。
6. **5–6分钟：源码。** 打开answer_output_node的引用合同、task_store的事件日志、import_milvus的提交顺序。
7. **6–7分钟：评测。** 解释相同预算四种检索、只有rerank完整生成，讲清小样本与引用存在性的限制。
8. **7–8分钟：复盘。** 展示空间URL、512token、Milvus主键三个真实问题；说明许可、公网和多worker尚未解决的范围。

## 演示异常时

模型限流、余额不足或VM网络断连时，保持真实失败界面，展示task_id与报告，不切成固定回答。可以讲解已完成的历史记录，但明确是历史实测。没有部署成功的公网Demo，不提供虚构URL。
